# 개발 흐름 설계

「Grok Bot 사용 후기」에 나온 개발 흐름을 이 환경(T3 Code, Claude·Codex, GitHub, Obsidian)에 맞게 옮긴 설계입니다. 에이전트가 따르는 규칙은 [`skills/dev-flow`](../skills/dev-flow/SKILL.md)와 [`skills/eco`](../skills/eco/SKILL.md)에 있습니다.

## 참고한 원칙

- **중간관리자(CoS)에게 맡긴다.** 매번 프롬프트를 직접 쓰지 않고, 맥락 정리와 작업 분배를 맡는 세션을 둡니다.
- **역할별로 컨텍스트를 나눈다.** 봇을 여러 개 두듯 세션마다 역할과 맥락을 분리합니다.
- **믿을 수 있는 루프를 만든다.** 위임하려면 작업 계획·순서와 완료 조건(test gate)이 필요하고, 통과하면 결과를 믿을 수 있는 검증이 있어야 합니다.
- **결정 단위를 PR에서 작업으로 키운다.** 작업 하나를 맡기면 여러 PR로 나누어 진행합니다.

후기의 흐름(맥락 수집 → 이슈화 → t3code 스레드에서 구현 → PR·리뷰, CI 실패나 리뷰 코멘트가 오면 다시 깨워 대응)을 아래 세션에 나눠 담았습니다.

## 세션 구성

프로젝트 폴더를 처음 만들 때 세 세션을 따로 둡니다. 폴더 없이 만든 세션은 간단한 질문용입니다.

| 세션 | 후기에서 대응하는 것 | 하는 일 | 모델 |
|---|---|---|---|
| 폴더 없음 | 기본 봇에 묻는 애매한 질문 | 간단한 질문 | Claude Haiku 5.5, effort low |
| [질문] | CoS, 맥락 수집 봇 | 질문 답변, 조사, 작업 카드 작성과 인계 | Claude Sonnet 5.5, effort medium |
| [작업] | t3code 코딩 스레드 | 구현, 커밋, PR, CI·리뷰 대응 | Claude Opus 5.5, effort high |
| [테스트] | 완료 조건(test gate) | 완료 조건 검증, 테스트 작성·실행, 결과 보고 | Claude Sonnet 5.5, effort medium |

- 폴더 없는 세션은 낮은 모델, [질문]은 중간 모델이라는 요청을 따랐습니다. [작업]과 [테스트]의 모델과 모든 effort 값은 제안입니다. 2026-11-25 기준 현재 설정은 이 T3 스레드 Opus 5.5 / max, Claude Code CLI `opus[1m]` / medium, Codex `gpt-6.2-astra` / ultra입니다.
- Codex로 만들 때는 `gpt-6-luna`(낮음), `gpt-6.2-sol`(중간), `gpt-6.2-astra`(높음)를 씁니다. T3 요금표의 토큰 단가 순서도 Claude는 Haiku 5.5 < Sonnet 5.5 < Opus 5.5, Codex는 이 나열 순서와 같습니다. 요금표 값이 제공자 직접 가격과 다를 수 있어 순서만 참고합니다.
- 테스트를 구현과 다른 세션에서 하는 이유는 구현 세션의 설명이 아니라 실행 결과로 판단하기 위해서입니다.

## 흐름

1. **맥락 정리 — [질문]**: 요구사항과 관련 코드를 확인하고 작업 카드를 씁니다. 필요하면 GitHub 이슈로 만듭니다(후기의 Linear 이슈화에 해당).
2. **인계**: 사용자가 요청하면 [질문]이 작업 카드를 [작업] 스레드로 보냅니다.
3. **구현 — [작업]**: 카드의 순서대로 구현하고 PR을 만듭니다. 큰 작업은 작은 PR 여러 개로 나눕니다. PR을 watch해 CI 실패, 리뷰 코멘트, 충돌이 생기면 다시 깨어나 대응합니다.
4. **검증 — [테스트]**: 카드의 완료 조건으로 PR을 검증하고 통과·실패를 근거와 함께 보고합니다. 실패는 [작업]으로 돌려보냅니다.
5. **머지와 기록**: 머지는 사용자가 결정합니다. 학습 노트는 Obsidian vault에만 저장하고 저장소나 PR에는 넣지 않습니다.
6. **정리**: 끝난 스레드는 settle 또는 archive합니다.

### 작업 카드

```text
목표: 끝났을 때 달라지는 것
범위: 할 일 / 하지 않을 일
순서: PR 단위 단계
완료 조건: 실행할 명령이나 확인 방법과 기대 결과
위험·미확인: 사용자 결정이 필요한 것
```

완료 조건은 후기에서 말한 "작업 계획/순서와 완료 조건(test gate)"에 해당합니다. 완료 조건을 정할 수 없으면 위임하기 전에 먼저 정합니다.

## 하위 세션 알림

`/handoff`로 넘긴 작업은 끝나거나(✅ 완료), 사용자 답이 필요하거나(❓ 질문), 막히면(⚠️ 중단) 넘겨받은 세션이 메인 세션으로 알림을 보냅니다(T3 `t3_thread_send`, queue). 메인 세션은 받은 알림을 아래처럼 강조해 보여 주고, 사용자가 지시하기 전에는 다음 작업을 시작하지 않습니다.

```markdown
## ✅ 완료 · [작업] <프로젝트> · <작업 이름>
> **결과** 무엇이 끝났는지 한두 줄
> **확인** 실행한 검증과 결과, 하지 못한 검증
> **다음** 사용자가 결정할 일, 없으면 "없음"
> **세션** <보내는 세션 link>
```

알림 하나가 메인 세션의 응답 한 번을 일으키므로, 중간 진행은 알림으로 보내지 않고 메인 세션에서 `/progress`로 확인합니다. `/progress`는 같은 프로젝트의 세션 상태, 최근 내용, 답이 필요한 질문을 표로 보여 줍니다.

## 명령

자주 하는 요청(확인·테스트·머지·커밋·푸시·PR·진행 상황·리뷰·세션 정리·노트)을 명령으로 만들었습니다. 최근 30일 요청 문구를 이 Mac 안에서 집계해 정했습니다.

| 명령 | 하는 일 |
|---|---|
| `/setup [폴더]` | [작업]·[질문]·[테스트] 세션 구성 |
| `/card [내용]` | 작업 카드 작성 |
| `/handoff [작업\|테스트]` | 카드를 넘기고 끝나면 알림 받기 |
| `/qa [PR\|브랜치]` | 완료 조건 검증 |
| `/progress [all]` | 다른 세션의 진행 상황과 질문 보기 |
| `/sessions [일수]` | T3 밖에서 실행한 세션 보기(T3는 이런 세션을 가져오지 않음) |
| `/commit`, `/pr`, `/merge` | 커밋, PR 생성과 감시, 확인 후 머지 |
| `/note [주제]` | Obsidian 학습 노트 |
| `/close [settle]` | 세션 보관 또는 완료 정리 |
| `/eco [on\|off]` | 토큰 절약 모드 |

- 리뷰는 Claude Code 기본 명령 `/code-review`, 앱 실행 확인은 `/run`을 씁니다. 기존 이름과 겹치는 `/review`, `/verify`, `/status`는 쓰지 않았습니다.
- Codex에서는 `$progress`처럼 `$`로 부릅니다.
- `/progress`와 `/eco`를 뺀 명령은 입력할 때만 불러오므로 평소 컨텍스트에 설명이 올라가지 않습니다.

## 토큰 절약 모드

요청할 때만 켜는 모드입니다. 요청하지 않으면 기존 방식대로 진행합니다.

- `/eco`를 입력하거나 "토큰 절약 모드로 해줘"처럼 요청하면 켜지고, `/eco off`나 끄라는 요청까지 유지됩니다.
- 켜지면 현재 스레드의 effort를 low로 낮추고(모델은 유지), 탐색 범위, 도구 출력, 위임, 검증 범위, 응답 길이를 줄입니다. 변경 파일이 5개를 넘거나, 새 의존성이 필요하거나, 설계를 바꿔야 하면 계속하기 전에 묻습니다.
- 각 스킬에도 절약 모드 기준이 있습니다. 예를 들어 `review-learning`은 학습 노트를 초안으로만 제공하고, `document-writing`은 새 문서를 요청할 때만 만듭니다.
- MCP 도구(플러그인)의 큰 출력은 `eco`의 도구 제한으로 줄입니다. `plugins/obsidian-note-inbox`는 LLM을 호출하지 않는 Python 프로그램이라 토큰 제한 대상이 아닙니다.

## 적용 상태 (2026-11-25)

| 항목 | 상태 |
|---|---|
| 폴더 없는 스레드 기본 모델 | T3 `No project`의 기본 모델을 Haiku 5.5 / low로 저장했습니다. T3 화면에서 새 스레드를 만들 때 이 값이 기본 선택되는지는 확인하지 않았습니다. |
| 새 프로젝트의 세 세션 | `dev-flow` 절차로 에이전트가 만듭니다. 임시 프로젝트에서 스레드별 모델 지정과 대기 스레드 생성을 확인한 뒤 삭제했습니다. |
| 이 저장소 밖에서 사용 | `install.sh`로 스킬과 명령을 `~/.claude/skills`, `~/.codex/skills`에 연결했습니다. 이 Mac의 모든 프로젝트와 폴더 없는 세션에서 쓸 수 있습니다. |
| 응답 언어 | 한국어 기본, 영어는 요청할 때만. 사실 기준 답변 규칙과 함께 `~/.claude/CLAUDE.md`, `~/.codex/AGENTS.md`에 넣었습니다. |
| 토큰 절약 모드 | `/eco`로 켜고 끕니다. 요청할 때만 동작합니다. |
| 사용자 할 일 알림 | 질문, 승인 요청, 응답 마지막 줄의 `🔔 할 일:`을 이 Mac(소리)과 휴대폰(ntfy)으로 알립니다([할 일 알림](../plugins/notify/README.md)). 하위 세션의 ✅·❓·⚠️ 알림을 받은 메인 세션도 할 일이 있으면 이 줄을 씁니다. |

## 후기와 다른 점

- **CoS**: 후기에서는 클라우드 봇(Grok Bot)이 원격 MCP로 t3code를 조작합니다. 여기서는 [질문] 세션과 사용자가 그 역할을 합니다. 이 T3 환경에서 Grok 제공자는 비활성 상태이고, 외부 에이전트를 T3 원격 MCP에 연결하는 구성은 확인하지 않았습니다.
- **실행 위치**: 세션이 이 Mac의 T3에서 실행되므로 Mac이 꺼져 있으면 진행되지 않습니다.
- **이슈 관리**: Linear 대신 GitHub 이슈를 씁니다.
- **자동화 범위**: T3에서 폴더만 추가하면 세 세션이 자동으로 생기지 않습니다. "세션 구성해줘"처럼 요청해야 합니다.
