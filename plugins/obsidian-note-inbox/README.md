# Obsidian 노트 로컬 수신기

명시적으로 지정한 기존 로컬 폴더에 표준 입력의 UTF-8 Markdown을 새 파일로 저장하는 수신 모듈입니다. Python 표준 라이브러리만 사용합니다. 수신 모듈 자체는 서버나 인증 기능이 없으며, 아래의 별도 Drive 가져오기와 자동 실행 구성에서 사용합니다.

## 사용

macOS/Linux에서 대상 폴더를 직접 지정합니다. 경로의 모든 구성 요소는 실제 디렉터리여야 하고 심볼릭 링크는 허용하지 않습니다. 실제 운영에서는 해당 vault의 노트 형식과 데이터 취급 규칙을 따르세요. 예시는 가상의 임시 폴더와 비개인정보입니다.

```sh
mkdir -p /tmp/note-inbox-example
INBOX="$(cd /tmp/note-inbox-example && pwd -P)"
printf '# 테스트\n\n학습 내용입니다.\n' | python3 plugins/obsidian-note-inbox/note_inbox.py \
  --inbox "$INBOX" --name example.md
```

실제 위치를 쓰려면 예시 경로를 **사전에 사용자가 선택하고 접근을 허용한 기존 디렉터리**의 절대 경로로 바꾸세요. 폴더는 자동 탐색하거나 만들지 않습니다. `--name`에는 경로를 넣지 않는 `.md` 파일명만 허용합니다. 실행 중 프로세스 인자에 대상 경로와 파일명이 보일 수 있으므로 민감정보를 파일명에 넣지 마세요. 입력 본문은 표준 입력으로 받으며 프로그램은 파일 내용이나 경로를 로그에 남기지 않습니다.

## 결과와 보장

- 종료 코드 `0`, 표준 출력 `created`: 새 파일 생성. 파일 권한은 `0600`입니다.
- 종료 코드 `0`, 표준 출력 `duplicate`: 동일한 파일명과 **바이트 단위로 동일한 내용**이 이미 존재합니다. 다시 쓰지 않습니다.
- 종료 코드 `3`: 동일 이름이 있으나 내용이 다르거나 심볼릭 링크라서 충돌했습니다. 원본은 그대로 둡니다.
- 종료 코드 `2`: 이름, 절대경로 형식 또는 본문이 유효하지 않습니다. 본문은 공백만으로 구성될 수 없고 UTF-8 및 최대 256 KiB여야 합니다.
- 종료 코드 `4`: 디렉터리가 없거나 접근할 수 없는 등 저장 실패입니다. 경로 구성 요소에 심볼릭 링크가 있는 경우도 여기에 포함됩니다.

경로가 포함된 이름, `.`으로 시작하는 이름, 제어 문자 및 `/ \\ : * ? " < > | # ^`는 거부합니다. 임시 파일에 내용을 모두 쓰고 동기화한 뒤 동일 디렉터리에서 기존 이름을 덮어쓰지 않는 원자적 하드 링크로 공개합니다. 다른 프로세스의 동시 요청도 이름 충돌로 처리합니다. 파일 시스템이 하드 링크를 지원해야 합니다. 프로그램이 강제 종료되면 숨겨진 `.note-inbox-*.md` 임시 파일이 남을 수 있으므로 운영자가 내용을 확인한 뒤 정리하세요. 완성된 파일이 디스크 전원 장애까지 보존된다고 보장하지는 않습니다.

이 수신기는 입력의 안전한 저장만 담당합니다. 전송 측의 인증, 메시지 기밀성, 민감정보 검토, Markdown/YAML 규칙 확인, 자동 실행 권한은 제공하지 않습니다. 네트워크에 직접 노출하거나 인증되지 않은 외부 요청에 연결하지 마세요.

## 테스트

저장소 루트에서 실행합니다. 테스트는 임시 디렉터리만 사용합니다.

```sh
python3 -m unittest discover -s plugins/obsidian-note-inbox/tests -v
```

## Google Drive 일회성 가져오기

`drive_pull.py`는 명시한 Drive 폴더의 직속 파일을 읽고 UTF-8 `.md` 파일만 위 수신기로 전달하는 일회성 클라이언트입니다. `drive_pull.py` 자체는 OAuth 로그인·토큰 갱신·스케줄링을 담당하지 않으며, 별도의 인증 공급자가 발급한 짧은 수명의 Google OAuth access token을 파일 디스크립터에서 받아야 합니다. 토큰을 프로그램 인자나 저장소 파일에 넣지 마세요.

```sh
# 인증된 토큰 공급자가 표준 출력으로 짧은 수명의 access token만 전달해야 합니다.
<token-provider> | python3 plugins/obsidian-note-inbox/drive_pull.py \
  --folder-id '<확인된-Drive-폴더-ID>' --inbox '<기존-로컬-폴더-절대경로>' --token-fd 0
```

`<token-provider>`는 실행 가능한 명령이 아닌 자리 표시자입니다. 로그인, 실제 공급자와 인증 범위가 준비되기 전에는 이 예시가 실행되지 않습니다. 이 프로그램은 Google Drive API의 파일 목록과 파일 읽기 요청만 보내고 원격 수정·이동·삭제 요청을 보내지 않습니다. 폴더 밖 항목, 하위 폴더, 바로가기, Google Docs 및 안전하지 않은 파일명은 무시합니다. 대상이 변경되거나 중복 파일명이 발견되면 가져오지 않고 충돌이나 실패로 셉니다. 같은 이름에 내용이 바뀐 경우 로컬 노트는 덮어쓰지 않습니다. 결과는 본문이나 파일명 없이 건수만 보여 주며 충돌·실패 시 0이 아닌 종료 코드를 반환합니다. 네트워크 리디렉션을 거부하고, 파일 크기와 요청 응답 크기를 제한합니다.

이 코드의 폴더 검사는 애플리케이션 수준 필터입니다. **OAuth 자격증명의 권한 자체를 해당 폴더로 제한하지 않습니다.** Google의 `drive.readonly`는 계정 전체에 대한 읽기 권한이고, `drive.file`은 특정 앱에 선택·허용된 파일에만 적용됩니다. 인증 방식과 실제 범위를 확인하지 않은 상태에서 넓은 권한을 부여하거나 장기 토큰을 저장하지 마세요. 참고: [Google Drive API 권한 범위](https://developers.google.com/workspace/drive/api/guides/api-specific-auth).

## Mac 자동 가져오기

`auto_pull.py`는 이 Mac의 전용 rclone 설정으로 액세스 토큰을 갱신한 후 기존 수신기를 실행합니다. 이 Mac에서 Google 인증 및 5분 간격 LaunchAgent를 설정했습니다. 클라우드 Claude가 만든 테스트 노트가 수집함에 저장되었습니다. 새 테스트 노트를 Drive에 올린 뒤 LaunchAgent를 수동 실행해 신규 저장, 바이트 일치, 중복 처리와 성공 종료를 확인했습니다. 2026-11-25 기준 `sync.log`에 5분 주기 실행 기록이 쌓여 있습니다. 로그인한 Mac이 켜져 있고 네트워크가 연결된 동안 실행되며, Drive에서 사라진 파일을 로컬에서 삭제하지 않고, 기존 파일을 덮어쓰지 않습니다.

개인 설정과 인증 정보는 `~/Library/Application Support/ClaudeObsidianInbox/`에 저장됩니다. 대상 Drive 폴더 ID와 수집함 경로는 저장소 코드가 아니라 그 폴더의 `config.json`(`folder_id`, `inbox`)에 둡니다. 선택 항목 `notify_command`를 주면 실행이 6번(약 30분) 연속 실패했을 때 그 명령으로 알림을 보내고, 계속 실패하면 약 12시간마다 다시 알립니다. 또 장기 토큰이 바뀐 시각을 재인증 시각으로 기록해(토큰 대신 짧은 해시만 `reauth.json`에 저장), 7일 만료 하루 전 낮 시간(09~22시)에 한 번 미리 알립니다. 재인증은 `/drive-reauth` 명령으로 합니다. 이 Mac에서는 [`notify`](../notify/README.md)로 휴대폰과 컴퓨터에 알립니다. 디렉터리와 설정 파일은 해당 사용자만 접근하도록 제한하지만 rclone 설정의 토큰 자체는 암호화되어 있지 않습니다. rclone의 Google Drive 읽기 권한은 계정 전체 범위이고, 이 프로그램은 별도로 지정된 전용 폴더만 읽습니다. 2026-11-22에 개인 Google Cloud 프로젝트의 전용 데스크톱 OAuth 클라이언트로 전환했고 LaunchAgent 실행에서 성공을 확인했습니다. 개인 앱은 현재 Google에서 테스트 상태이므로 Drive 읽기 권한의 갱신 토큰은 발급 7일 후 만료됩니다. 2026-11-25에 재인증했으므로 2026-12-02경부터 자동 수집이 멈출 수 있으며(그 뒤 약 30분 연속 실패하면 알림이 옵니다), 지속적으로 사용하려면 재인증하거나 Google의 게시 요건(공개 홈페이지와 개인정보처리방침 등)을 충족해야 합니다. 테스트 상태에서는 지정된 사용자만 접근합니다. 참고: [Google OAuth 토큰 만료 정책](https://developers.google.com/identity/protocols/oauth2#expiration). 로그에 본문이나 토큰은 기록하지 않습니다.

로그 확인: `~/Library/Application Support/ClaudeObsidianInbox/sync.log`와 `sync-error.log`. 실행 중 오류나 충돌은 다음 주기에 다시 확인합니다. 같은 이름의 로컬 노트와 내용이 다르면 충돌로 남기므로 수동 확인이 필요합니다. Drive에서 기존 노트를 수정해도 로컬 파일을 갱신하지 않는 단방향 신규 수집입니다.

테스트 상태에서 재인증이 필요할 때는 Mac 터미널에서 `/opt/homebrew/bin/rclone --config "$HOME/Library/Application Support/ClaudeObsidianInbox/rclone.conf" config reconnect claude-obsidian-inbox:`를 실행하고, 본인 계정의 기존 읽기 권한을 승인합니다. Google의 테스트 상태에서는 다시 발급한 갱신 토큰도 7일 후 만료됩니다. 이전 공용 인증 설정은 같은 폴더의 사용자 전용 `rclone-shared-backup.conf`에 남겨 두었으며 자동 사용하지 않습니다. 두 설정에는 인증 정보가 있으므로 공유하지 마세요.
