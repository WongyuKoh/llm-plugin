# T3 세션 작업 규칙

## 적용 범위

T3 Code 안에서 세션 상태를 조회·정리하거나 사용자가 세션 종료·재연결을 요청했을 때 사용한다. 현재 환경에 노출된 도구 스키마를 먼저 확인한다. 도구가 없으면 수행했다고 말하지 않고 제한을 설명한다. 로컬 로그의 수정 시간만으로 실행·승인·완료 상태를 추정하지 않는다. 새 프로젝트의 역할 세션 구성과 세션별 모델은 `dev-flow`를 따른다.

## 진행 상황과 입력 요청

- 여러 단계의 작업은 사용 가능한 계획 도구로 단계와 현재 진행 상태를 유지한다. 간단한 작업에는 불필요한 계획을 만들지 않는다.
- 다른 세션 현황을 한 번에 보여 줄 때는 `progress` 스킬의 형식을 쓴다. 다른 세션 현황은 `t3_thread_list`로 필요한 프로젝트 범위부터 확인한다. 세션 내용을 설명하기 전에는 `t3_thread_read`로 확인한다. 상태를 요약할 때 출처의 갱신 시각과 실제 링크를 함께 사용한다.
- `waiting`만 보고 사용자 입력 필요라고 단정하지 않는다. `pendingRequestCount`, 활동 기록, 대기 중인 하위 작업을 확인해 사용자 입력 대기와 작업 대기를 구분한다.
- 입력이 필요한 경우 실제 질문/승인 도구를 사용한다. 텍스트에 '알림'을 적은 것만으로 시스템 알림이 발송됐다고 주장하지 않는다. 푸시 알림은 T3와 기기의 알림 설정에 맡긴다.
- 답변은 결과와 다음 행동을 먼저, 짧게 작성한다. 세션 관계는 실제 parentThreadId와 delegatedFrom 등의 근거가 있을 때만 표현한다. 하위 에이전트를 임의로 만들지 않는다.

## 완료와 종료

- 한 응답 또는 run의 `completed`는 작업 전체 완료와 다르다. 요청한 결과, 필요한 검증, 미해결 작업을 확인한 뒤 완료라고 말한다.
- 사용자가 이 세션을 '종료', '보관', '여기까지 하고 종료'하라고 명확히 요청하면 `t3_thread_organize`의 `archive`로 현재 세션을 보관한다. 현재 세션 대상은 threadId 생략을 지원하는지 도구 스키마로 확인한다. 인용문·코드·예시 속 '종료', 서버나 프로세스 종료 요청에는 적용하지 않는다.
- 진행 중인 하위 작업이나 중요한 미처리 요청이 있으면 보관 가능 여부를 확인한다. 보관을 위해 다른 작업을 임의 취소하거나 승인하지 않는다. 도구가 거절하면 이유를 설명한다.
- 사용자가 '완료 목록으로 정리'를 요청하면 `settle`을 사용한다. archive와 settle을 혼동하지 않는다. 일반적인 작업 완료만으로 자동 보관하지 않는다.
- 도구의 성공 결과를 확인한 뒤 보관/정리 결과를 알린다. 실패나 요청 접수를 실제 완료로 바꾸어 표현하지 않는다.

## 관련 작업 이어가기

- 새 요청이 기존 작업과 관련되면 접근 가능한 프로젝트의 세션 목록/검색에서 후보를 찾고 실제 내용을 읽어 관련성을 확인한다. 제목의 단어 일치만으로 복원하지 않는다.
- 현재 목록 도구가 archived 항목 조회를 지원하지 않으면 전체 보관함을 검색했다고 말하지 않는다. 알려진 세션 링크/ID가 있으면 그 세션을 읽는다. `settled`는 `archived`와 별개다.
- 사용자가 특정 관련 세션을 이어가기로 명확히 선택하면 상태에 따라 `unarchive` 또는 `unsettle`을 실행한다. 단순 후보 발견만으로 다른 세션을 변경하지 않는다.
- 세션 링크를 제공하는 것과 사용자의 화면을 전환하는 것은 별개다. 실제 전환 기능이 없다면 링크로 안내한다. 새 최상위 세션은 사용자가 요청한 경우에만 만든다.

## 시각화

실제 세션 목록·부모 관계·상태를 기반으로 표나 요청된 HTML 시각화를 만들 수 있다. 정적 캡처에는 기준 시각을 표시한다. 스킬 자체는 백그라운드 구독이나 지속 갱신 UI가 아니므로 이를 실시간 대시보드라고 부르지 않는다. 지속 갱신되는 세션 목록은 T3 기본 화면이 담당한다.

토큰 절약 모드(`eco`)에서는 목록·읽기 도구에 작은 `limit`을 주고, 필요한 세션만 읽는다.
