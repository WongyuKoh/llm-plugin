# 리뷰와 학습 기록

리뷰, PR 설명, 머지 메시지를 준비할 때 실제 diff, 관련 맥락, 확인한 테스트를 살펴보고 변경 목적과 동작, 검증 결과, 남은 위험을 사실에 맞게 작성한다. 리뷰 요청이라면 결함과 근거를 먼저 제시하고, 확인하지 못한 내용은 확인한 것처럼 쓰지 않는다. 저장소 템플릿과 사용자의 명시적 요구를 따른다.

## 작성 표기

새로 작성하는 리뷰·PR 본문·커밋·머지 메시지에 Claude 또는 AI가 작성했다는 자동 홍보 문구나 불필요한 `Co-Authored-By` 트레일러를 추가하지 않는다. 기존 작성자 정보나 타인의 기여를 임의로 삭제하지 않고, 저장소 정책이나 사용자가 명시적으로 요구한 귀속 표기는 보존한다. 이미 게시된 내용이나 기존 커밋 기록은 요청 없이 수정하거나 다시 쓰지 않는다.

## Obsidian 내용과 저장소 분리

학습 노트는 Obsidian vault에만 저장한다. 노트 본문, vault에서 읽은 내용, vault 경로와 노트 링크를 프로젝트 저장소의 파일·커밋·PR·이슈·리뷰 코멘트에 넣지 않는다. 노트에서 PR·커밋을 링크하는 것은 괜찮지만, 저장소 쪽에서 노트를 가리키지 않는다.

## Obsidian에 학습 내용 연결

1. 사용자가 지정한 Obsidian vault와 저장 폴더가 있는지 현재 지시사항이나 프로젝트 설정에서 확인한다. 알 수 없다면 경로를 지어내거나 무작정 vault를 탐색하지 말고 사용자에게 위치를 물어본다. 위치를 기다리는 동안 가능한 리뷰·PR 초안 작업은 계속한다. 로컬 vault에 접근할 수 없는 환경(claude.ai 웹·모바일 등)에서는 사용자 지침에 지정된 Google Drive 수집 폴더에 Markdown 파일로 저장한다. 그 폴더를 모르면 묻고, Drive에 저장한 것을 vault에 저장했다고 말하지 않는다.
2. 위치와 기록 권한이 확인되면 vault의 지침, 기존 노트 형식과 관련 노트를 필요한 범위에서 살펴보고 새 노트를 만들거나 적절한 노트를 갱신한다. 저장 위치, 속성, 민감도, 링크는 해당 vault의 규칙을 따른다. 기존 내용을 덮어쓰지 않는다. 단순히 미리보기만 요청했다면 노트도 초안으로 제공한다.
3. 학습에 필요한 내용만 적는다: 변경 배경과 핵심 동작, 주요 구현과 선택 이유, 이해할 개념과 참고할 코드 경로, 검증 및 남은 질문. 코드와 diff에 근거하지 않는 설명은 추측이라고 표시하고 민감한 정보는 옮기지 않는다.
4. 관련 프로젝트·개념 노트가 실제로 있으면 해당 vault에서 사용하는 방식으로 링크한다. PR URL이나 커밋 링크가 확인되면 노트에 포함하고, 접근 가능한 링크가 없다면 저장소·브랜치·관련 파일 등 확인된 식별 정보를 남긴다. 노트가 아직 없으면 링크가 이미 존재하는 것처럼 설명하지 않는다.
5. 사용자에게 생성 또는 수정한 노트의 경로와 실제 연결 상태를 알린다. 노트 작성이나 링크가 불가능하면 이유와 함께 붙여 넣을 수 있는 학습 노트 초안을 제공한다.

PR 게시, 리뷰 제출, 머지 및 원격 변경은 사용자의 요청과 해당 환경의 권한 범위에서만 수행한다. 학습 노트 작업 자체가 이런 외부 작업의 승인을 뜻하지 않는다.

토큰 절약 모드(`eco`)에서는 diff와 실행한 테스트만 근거로 쓴다. 학습 노트는 vault를 탐색하지 않고 짧은 초안을 응답에만 제공하며, vault 저장은 사용자가 요청할 때 한다.
