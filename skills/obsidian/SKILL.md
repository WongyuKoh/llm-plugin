# Obsidian 연결

프로젝트 폴더의 문서를 Obsidian vault에서 보이게 하고, 그 폴더에서 여는 Claude·Codex 세션이 처음부터 vault 규칙을 따르게 한다. 저장소에 올라가는 파일 변경은 지금 체크아웃된 브랜치가 아니라 기본 브랜치에 적용한다. 인자: `$ARGUMENTS`

## 1. 대상 확인

- 인자의 첫 단어가 `/`, `~`, `.`로 시작하면 대상 폴더, 나머지는 분류(예: 개인, 회사 이름, 연구)다. 경로 인자가 없으면 현재 프로젝트 루트(git 저장소면 최상위, 아니면 작업 폴더)를 대상으로 한다.
- 경로가 디스크에 없으면 `/setup`이나 새 폴더 만들기 흐름에서 불렸을 때만 만든다. 그 밖에는 만들지 물어본다.
- vault 위치는 현재 지침(전역 지침이나 프로젝트의 로컬 지침)에서 확인한다. 모르면 묻는다. vault를 추측해서 찾지 않는다.
- 대상 폴더가 vault 안이거나 vault의 상위 폴더면 연결하지 않고 이유를 알린다.
- vault의 공통 에이전트 지침, 탐색 지도, 노트 작성 규칙, 프로젝트 연결 안내를 읽는다. 아래 절차보다 vault 문서가 구체적이면 vault 문서를 따른다.

## 2. 이미 연결됐는지 확인

- vault의 프로젝트 영역에서 대상 폴더의 문서 폴더나 회의록 폴더를 가리키는 심볼릭 링크를 찾는다. `.obsidian`, 템플릿, 백업, 보관 폴더는 뒤지지 않는다.
- 대상 폴더의 `CLAUDE.local.md`에 "Obsidian 연동" 절이 있는지 본다.
- git 저장소면 기본 브랜치의 `.gitignore`에 vault 규칙이 요구하는 제외 항목이 있는지 본다(아래 4절).
- 모두 갖춰졌으면 아무것도 바꾸지 않고 연결 위치만 알린다. 빠진 것만 채운다.

## 3. 분류 고르기

- vault의 탐색 지도와 연결 안내에 있는 프로젝트 영역(개인, 회사별 업무, 연구 등)으로 후보를 만든다. 후보를 지어내지 않는다.
- 인자로 분류를 받았고 후보 중 하나와 맞으면 묻지 않는다. 아니면 후보를 번호 목록으로 보여 주고 고르게 한다. 질문 도구가 있으면 그 도구를 쓴다.
- 링크 이름은 vault의 기존 연결과 같은 방식(`프로젝트_docs`, 회의록 링크는 연결 안내의 방식)으로 정한다.

## 4. git 저장소의 기본 브랜치에 적용

대상 폴더가 git 저장소가 아니면 이 절을 건너뛴다.

변경을 두 가지로 나눈다.

- **브랜치와 무관한 것**: `CLAUDE.local.md`, git이 무시하는 폴더 안의 파일, `.git/info/exclude`, vault의 링크. 작업 폴더에 바로 만든다.
- **저장소에 올라가는 것**: `.gitignore` 수정, git이 추적하는 `docs/` 안의 새 파일. 기본 브랜치에만 적용한다.

기본 브랜치를 정한다.

1. 원격을 받아 온다(`git fetch`). 원격 기본 브랜치는 `git ls-remote --symref <원격> HEAD`로 확인한다. 포크면 `upstream`을 먼저 본다.
2. 원격 기본 브랜치가 `main`이면 `main`을 쓴다. 다른 이름(예: `development`)이면 그 브랜치를 쓰고, 오래 쓰지 않은 `main`이 있더라도 그쪽에는 적용하지 않는다. 판단하기 어려우면 묻는다.

기본 브랜치에 적용한다.

- 지금 기본 브랜치에 있으면 작업 폴더에서 고친다.
- 다른 브랜치에 있으면 그 브랜치의 작업 폴더를 건드리지 않는다. 임시 worktree에 기본 브랜치를 꺼내 고친다.
  - 로컬 기본 브랜치가 원격보다 뒤처졌으면 먼저 fast-forward로 맞춘다.
  - fast-forward가 안 되면 멈추고 알린다.
  - 끝나면 worktree를 지운다.
- 커밋에는 이 스킬이 바꾼 파일만 넣는다. 다른 사람의 변경이나 작업 중인 파일은 넣지 않는다.
  - 커밋 메시지 예: `회의록 폴더를 Git에서 제외`
  - 푸시와 PR은 사용자가 요청할 때만 한다.
- 지금 브랜치에서도 바로 무시되도록, 같은 제외 항목을 `.git/info/exclude`에 더한다.
- 다른 브랜치의 작업 폴더에 같은 수정이 커밋되지 않은 채 남아 있으면, 기본 브랜치에 커밋한 뒤 되돌린다. 내용이 이 스킬의 수정과 정확히 같을 때만 되돌린다. 그래야 기능 PR에 섞이지 않는다.
- 팀 저장소의 기본 브랜치에 직접 커밋하면, 다음에 원격을 받을 때 갈라질 수 있다. 알릴 때 이 점과 푸시 여부를 함께 쓴다.

## 5. 프로젝트 쪽 준비

- 문서 폴더는 `docs/`다. `doc/`처럼 다른 이름의 문서 폴더가 이미 있으면 그 폴더를 문서 링크에 쓸지 묻는다. 회의록은 vault 규칙에 따로 정해져 있으면 그 위치(예: `docs/회의록/`)를 쓴다.
- `docs/`가 없으면 만든다. `docs/README.md`가 없으면 프로젝트 이름과 `회의록/` 폴더 안내만 담은 짧은 입구를 만든다. 확인하지 못한 프로젝트 설명은 쓰지 않는다.
  - `docs/`가 git에 추적되는 폴더면 이 파일은 저장소에 올라가는 변경이다(4절).
  - 개인 문서라 저장소에 올리면 안 되는 폴더면 `.git/info/exclude`로 제외한다.
- `docs/회의록/`을 만든다. 회의록은 `minutes` 스킬이 이 폴더에 저장한다.
- vault 연결 안내에 Git 제외 규칙(예: `.gitignore`에 `/docs/회의록/` 등록)이 있으면 4절대로 기본 브랜치에 적용한다.
- 기존 파일은 덮어쓰지 않는다.

## 6. 세션 지침 넣기

`CLAUDE.local.md`는 Claude가 매 세션 자동으로 읽는 개인 지침이다. Codex는 전역 지침의 안내로 이 파일을 읽는다. 파일이 없으면 만들고, 있으면 기존 내용을 지키고 끝에 아래 절을 더한다. `<>`는 확인한 실제 값으로 바꾼다.

```markdown
# Obsidian 연동

- 로컬 vault: `<vault 절대 경로>`. vault 노트를 만들거나 고치기 전에는 vault의 `<공통 에이전트 지침>`, `<탐색 지도>`, `<노트 작성 규칙>`을 읽고 따른다.
- 이 프로젝트의 문서 원본은 `<문서 폴더>/`이고, vault에서는 `<vault 안 문서 링크의 상대 경로>`로 연결돼 있다. 회의록·보고서·계획서는 문서 폴더 안에 쓴다.
- 회의록은 `/minutes`(Codex는 `$minutes`)로 `docs/회의록/`에 저장한다. vault에서는 `<회의록 링크의 상대 경로, 없으면 이 줄의 이 문장을 뺀다>`로 연결돼 있다. 학습 노트는 `/note`로 vault에 저장한다.
- 저장소 설정 변경은 기본 브랜치 `<기본 브랜치>`에 적용한다.
- 민감도 기본값: <vault 규칙에 따른 값. 회사 업무면 confidential>
- vault 노트 내용과 경로는 저장소 파일, 커밋, PR, 이슈에 넣지 않는다.
- 이 경로는 이 Mac에서만 쓸 수 있다. vault에 접근할 수 없으면 읽거나 저장했다고 말하지 않는다.
```

- git 저장소면 `git check-ignore CLAUDE.local.md`로 무시되는지 본다. 무시되지 않으면 `.git/info/exclude`에 `CLAUDE.local.md`를 더한다. 저장소에 올라가는 `.gitignore`, `CLAUDE.md`, `AGENTS.md`에는 vault 정보를 넣지 않는다.

## 7. vault 쪽 연결

vault의 프로젝트 연결 안내 절차를 따른다.

1. 고른 영역의 프로젝트 폴더에 문서 폴더를 가리키는 심볼릭 링크를 만든다. 기존 링크처럼 상대 경로로 만든다. 같은 이름이 있으면 멈추고 알린다.
2. 연결 안내에 회의록 전용 연결(회의록 폴더만 가리키는 링크)이 있으면 같은 방식으로 만든다.
3. 연결 안내의 해당 표에 한 줄씩 더한다(문서 연결, 회의록 연결).
4. 해당 영역의 허브나 프로젝트 목록에 링크를 더한다.
5. 고친 vault 문서의 `updated`를 오늘 날짜로 바꾼다. 다른 내용은 바꾸지 않는다.

## 8. 확인과 알리기

- 확인할 것:
  - 링크가 실제 폴더를 가리킨다.
  - 기본 브랜치의 `.gitignore`에 제외 항목이 있다(`git show <기본 브랜치>:.gitignore`).
  - `git check-ignore`로 회의록 폴더와 `CLAUDE.local.md`가 무시된다.
  - `git status`에 이 스킬이 만든 파일이 나오지 않는다.
- 알릴 것:
  - 만든 폴더와 파일
  - 기본 브랜치 이름, 만든 커밋, 푸시 여부
  - vault 안 링크 위치와 고친 vault 문서
  - 확인 결과
- 지금 열린 세션은 새 `CLAUDE.local.md`를 아직 읽지 않았다. 새 세션부터 적용되며, 열린 세션은 `/refresh`로 다시 읽을 수 있다고 한 줄로 알린다.
- 하지 못한 단계가 있으면 이유와 사용자가 직접 할 명령을 쓴다.
