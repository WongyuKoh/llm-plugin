# 세션 목적과 범위 관리

## 시작

이 세션의 첫 작업에서 사용자의 요청과 현재 맥락으로 목적을 파악하고, 짧은 이름과 한 문장의 목적을 알린다. 이름은 나중에 찾기 쉽도록 `프로젝트 · 작업 종류 · 대상`처럼 구체적으로 제안한다. 목적이 충분히 명확하면 묻지 말고 제안한 범위로 작업을 시작한다. 명확하지 않아 안전하거나 적절한 진행이 불가능할 때만 필요한 내용을 질문한다. 이미 정해진 목적이나 사용자가 지정한 이름이 있으면 그대로 따른다.

실제 세션 이름은 사용 가능한 세션 이름 변경 기능이 있을 때만 설정한다. 기능을 직접 사용할 수 없다면 이름을 바꾸었다고 주장하지 말고 사용자가 설정할 수 있게 제안 이름을 보여준다. Claude Code에서는 사용자가 `/rename 제안한 이름`을 입력할 수 있다. 작업을 진행하기 위해 이름 변경을 기다릴 필요는 없다.

## 진행 중 주제 확인

새 요청을 현재 목적, 직전 요청 및 사용자의 후속 지시와 비교한다. 버그 수정, 검증, 설명, 후속 질문처럼 기존 작업을 완수하는 데 필요한 일은 관련 작업으로 처리한다. 주제가 확실히 다르거나 관련성을 판단하기 어렵다면, 독립 작업을 시작하기 전에 현재 목적과 새 요청을 짧게 짚고 다음 선택지를 제시한다.

- 현재 세션에서 계속하기
- 관련된 기존 세션으로 옮기기
- 새 세션을 만들어 진행하기

접근 가능한 세션 목록이나 사용자가 제공한 정보가 있을 때만 실제 관련 세션을 이름이나 링크로 추천한다. 목록을 볼 수 없다면 특정 세션의 존재나 내용을 추측하지 말고, 기존 세션을 검색하거나 새 세션을 만들도록 권유한다. 실제 세션 생성·전환을 지원하는 도구가 없으면 사용자에게 해당 조작을 안내하고, 수행했다고 주장하지 않는다.

요청이 다른 주제라는 점이 명백하고 사용자가 이 세션에서 계속하라고 이미 지시했다면 다시 묻지 않고 진행한다. 사용자가 범위를 바꾸거나 여러 주제를 함께 다루기로 선택하면 그 결정을 따르고 세션 목적과 제안 이름을 갱신한다. 명시적인 사용자 지시가 이 스킬의 권유보다 우선한다.

T3 역할 세션(`[작업]`·`[질문]`·`[테스트]`)에서 역할에 맞지 않는 독립 작업을 받으면 맞는 역할 세션을 먼저 제안한다(`dev-flow`). 역할 안의 후속 작업과 사용자가 이 세션에서 하라고 한 일은 그대로 진행한다.

## 세션을 나눌 때 인계

사용자가 세션 분리를 선택하면 새 세션의 제안 이름과 목적, 지금까지 확인된 관련 사실, 다음 작업, 필요한 파일이나 링크를 간결한 복사 가능한 시작 메시지로 정리한다. 확인하지 못한 사실이나 다른 세션의 상태를 만들어내지 않는다. 비밀 값이나 불필요한 개인정보는 인계 내용에서 제외한다.

토큰 절약 모드(`eco`)에서는 이름과 목적을 한 줄로 알리고, 다른 세션 목록은 사용자가 요청할 때만 조회한다.
