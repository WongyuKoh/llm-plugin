# 작업 넘기기

인자: `$ARGUMENTS`. 첫 단어가 `테스트`면 [테스트] 세션, 그 밖에는 [작업] 세션에 넘긴다. 나머지는 추가 지시로 카드 뒤에 붙인다.

1. 이 대화의 가장 최근 작업 카드를 쓴다. 없으면 `/card` 절차로 먼저 만들어 보여 준다.
2. 현재 프로젝트에서 대상 역할 세션을 `t3_thread_list`(`titleContains`)로 찾는다. 이 세션에 `[세션 범위]` 주제가 있으면 `[작업] <주제>`(또는 `[테스트] <주제>`)를, 없으면 `[작업]`(또는 `[테스트]`)을 찾는다. 없으면 넘기지 않고 `/setup`을 안내한다. 여러 개면 사용자에게 고르게 한다.
3. `t3_thread_configure`(인자 없음)로 이 세션의 `threadId`를 확인한다. 이 값이 알림을 받을 메인 세션이다.
4. 아래 메시지의 `<프로젝트>`, `<작업 이름>`(카드 목표를 짧게), `<대상 세션 link>`를 보내기 전에 실제 값으로 채운다. 받는 세션은 자기 링크나 프로젝트 이름을 모를 수 있다.
5. `t3_thread_send`(`mode: "queue"`)로 대상 세션에 메시지를 보낸다.
6. 대상 세션의 `link`와 "끝나거나 질문이 생기면 이 세션에 알림이 옵니다"를 한 줄로 알린다.

````text
[작업 요청] 메인 세션: <이 세션 threadId>

<작업 카드>
<추가 지시>

보고 규칙
- 완료 조건까지 끝나면 ✅ 완료, 사용자 답이 필요하면 ❓ 질문, 막히거나 실패하면 ⚠️ 중단 알림을 t3_thread_send(threadId: 메인 세션, mode: "queue")로 보낸다. 중간 진행은 보내지 않는다.
- 형식은 아래와 같다. 제목과 세션 줄은 그대로 쓰고 나머지만 채운다. 항목은 목록으로 한 줄씩 쓰고, `>` 인용 줄로 이어 쓰지 않는다(한 문단으로 합쳐진다).

  ## ✅ 완료 · [작업] <프로젝트> · <작업 이름>

  - **결과**: 무엇이 끝났는지 한두 문장
  - **확인**: 실행한 검증과 결과, 하지 못한 검증
  - **다음**: 사용자가 결정할 일, 없으면 "없음"
  - **세션**: <대상 세션 link>

- ❓ 질문은 **결과** 대신 **질문**(한 문장)과 **선택지**(번호 목록, 한 줄에 하나)를, ⚠️ 중단은 **원인**과 **필요한 조치**를 쓴다.
- 할 일이 여러 개면 이 세션의 작업도 `parallel` 스킬로 나눠 동시에 진행한다.
- 이 세션의 응답에는 `🔔 할 일:` 줄을 쓰지 않는다. 사용자 알림은 메인 세션이 보낸다.
````
