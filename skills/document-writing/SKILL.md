# 문서 작성

- 문서의 목적, 독자, 산출물과 저장 위치를 요청 및 기존 문서에서 파악한다. 알 수 없는 내용은 추측하지 말고 확인 가능한 범위를 먼저 작성한 뒤 필요한 정보만 묻는다.
- 관련 코드, 설정, 변경 내역과 기존 문서를 살펴보고 확인한 사실과 제안, 미확인 사항을 구분한다. 경로, 명령어, 링크와 예시는 실제 환경에서 확인한 것만 사용한다.
- 독자가 행동할 수 있도록 필요한 배경, 절차 또는 결정, 검증 방법과 남은 작업을 담는다. 이미 있는 형식과 언어를 따르고, 적절한 기존 문서를 갱신해 중복을 줄인다.
- 변경한 문서의 링크와 명령어를 가능한 범위에서 확인하고, 결과와 확인하지 못한 부분을 사용자에게 보고한다.
- PR 설명이나 리뷰 결과를 작성하는 경우에도 사실에 근거해 변경 이유와 검증 결과를 적고, 사용자가 요청하지 않은 Claude 작성 홍보 문구는 넣지 않는다. 기존 정책이나 필수 고지는 유지한다.
- Obsidian vault의 노트 내용과 경로는 저장소 문서에 옮기지 않는다.
- 토큰 절약 모드(`eco`)에서는 기존 문서의 필요한 부분만 고치고, 새 문서는 사용자가 요청할 때만 만든다.
