# 새 세션으로 이어가기

인자: `$ARGUMENTS`. 있으면 새 세션이 받자마자 할 일이다. 없으면 새 세션은 이어받았다는 확인과 남은 일만 쓰고 사용자 지시를 기다린다.

## 언제 쓰나

- 메뉴 막대에 "이 세션이 길어졌습니다 … 새 세션으로 이어가기" 또는 "이 세션이 압축됐습니다 …"가 뜬 때. 응답이 끝날 때 컨텍스트가 창의 80%를 넘었거나 압축이 일어나면 notify 플러그인이 이 할 일을 넣는다.
- 압축된 뒤라면 이 세션에 남은 것은 요약이다. 요약에 없는 세부는 T3에 남은 이 세션의 전체 대화를 `t3_thread_read`로 읽어 채운다. T3 기록은 압축과 상관없이 남아 있다.

## 순서

1. 이 세션 정보를 확인한다.
   - `t3_thread_configure`(인자 없음): threadId
   - `t3_thread_read`(threadId: 이 세션, `limit: 1`): 제목, 브랜치, worktree 경로, 연결된 PR
   - 저장소: `git status --short`, 브랜치, 최근 커밋. 커밋하지 않은 변경이 이 세션의 것인지 다른 세션의 것인지 구분한다.
   - 이 세션이 띄운 하위 세션·연계 세션(`↳`)과 그 상태(`t3_thread_list`, `includeSubagents: true`)
2. 실행 중인 하위 세션(`delegate_task`)이 있으면 끝날 때까지 기다렸다가 이어간다. 결과는 이 세션으로 오기 때문이다. 연계 세션(`↳`)은 보고 받을 세션이 바뀌었다고 새 세션을 만든 뒤 알린다(5번).
3. 아래 형식으로 인계 메시지를 쓴다. 새 세션은 이 대화를 볼 수 없으므로 필요한 사실을 모두 넣는다. 짐작은 짐작이라고 쓰고, 비밀 값은 넣지 않는다.
4. `t3_thread_launch`로 새 세션을 만든다.
   - `title`: `<이 세션 제목> · 이어서 2`. 이 세션 제목이 이미 `· 이어서 N`으로 끝나면 `N+1`로 바꾼다. `[작업]` 같은 역할 표시는 그대로 둔다(새 세션이 그 역할을 이어받는다).
   - `message`: 인계 메시지
   - 모델과 모드는 넣지 않는다(이 세션 것을 물려받는다).
   - 이 세션이 worktree에서 일했으면 `workspaceStrategy: { type: "existing_worktree", worktreePath: <그 경로> }`, 아니면 넣지 않는다.
   - `delegatedFrom`은 쓰지 않는다. 새 세션은 다른 에이전트가 맡은 일이 아니라 사용자가 이어서 쓰는 세션이다.
5. 넘길 것을 옮긴다.
   - 연결된 PR: `link_pull_request`(threadId: 새 세션). 이 세션이 감시하던 PR이면 `watch_pull_request`(threadId: 새 세션)를 걸고 이 세션은 `unwatch_pull_request`로 끈다.
   - 연계 세션(`↳`): `t3_thread_send`로 "보고 받을 세션이 <새 세션 threadId>로 바뀌었다"를 보낸다.
6. 이 세션 제목 앞에 `(이어감) `을 붙인다(`t3_thread_update`, `action: "rename"`). 메뉴 막대가 이 세션에 이어가기 제안을 다시 넣지 않고, `/handoff`가 이 세션을 역할 세션 후보에서 뺀다.
7. 새 세션 `link`와 넘긴 것(PR, 연계 세션)을 짧게 알린다. 이 응답에는 `🔔 할 일`을 쓰지 않는다. 남은 할 일은 새 세션이 이어받아 적는다. 이 세션을 정리하려면 `/close`를 쓰면 된다고 한 줄로 덧붙인다.

T3 도구가 없는 환경(T3 밖 터미널 등)이면 인계 메시지를 코드 블록으로 보여 주고, 새 세션을 열어 그대로 붙여 넣으라고 안내한다. 제목을 바꾸지 않는다.
